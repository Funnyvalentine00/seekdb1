## 改动及收益归因

仅修改生产文件 `tools/hipvs_bridge/seekdb_bf_gemm.cpp`：将完整64×64 WMMA块
的累加器经16KiB共享内存写回，直接输出 `norm[b]-2*dot`，省去独立距离矩阵
全局读写及一次启动。尾块和不支持WMMA的形状保留rocBLAS，C ABI不变。
默认启用；`SEEKDB_CUVS_GEMM_FUSED_NORM=0`恢复原WMMA计算，
`SEEKDB_CUVS_BF_GEMM=0`使用原cuVS BF fallback。

E01的部分真实剖析中，Top-K占GPU内核时间36.40%，额外norm步骤25.75%，
WMMA23.28%，merge10.70%，因此选择消除额外矩阵访问。该剖析有一次hipFree
长达191.6秒，已终止，剖析墙钟时间无效。只用内核统计选择方向，性能结论
来自未开启剖析的正式配对。候选每次记录1830 fused /1830 WMMA /138 BLAS tiles，
返回成功且没有静默回退。独立审查已重算原始样本并核对执行计数。

GEMM为712.5MiB，增加约9.3%。峰值来自2ms采样，非保证捕获瞬时最高值。

GPU利用率接口始终显示100%，低功率空闲时也如此，故不能作为实际占用率或独占证明。

部分剖析记录H2D设备拷贝12.141ms、D2D24.282ms、D2H .0247ms；另外492次
hipMemcpy2D的CPU API累计185.928ms，139次hipMemcpy累计57.448ms。
这些是跨两次构建的部分轨迹，2D传输和等待不能只由copy engine统计代表，
也不能把CPU API等待与其内部GPU时间相加。完整CPU数据准备、PCIe和SQL扫描
的独立计时未建立，**不能断言传输已不是瓶颈**。
